

## 1. 목표와 범위 설정

- 어떤 시스템을 디지털 트윈할 것인지 정의
- 입력, 출력, 사용 목적을 설정

해당 프로젝트는 **단일 무부하 서보모터(1-DOF)를 Newton 물리 엔진을 통해 모델링**하고, 실측 데이터 기반으로 파라미터 피팅을 하여 디지털 트윈한다.

## 2. 로그와 신호 정의

- 실측에서 어떤 신호를 측정할지 설정
- 단위, 샘플링 주기, 시간축 정렬 방식도 설정

**Command Position**을 입력으로 주어 **Feedback Position, Feedback Velocity, Feedback Torque**를 출력으로 받아 이 4개의 신호를 모터의 *parameter fitting*에 사용하였다.  

샘플링 주기는 **1ms**, 시간축 정렬은 **Command Position을 기준**으로 실측과 시뮬레이션 데이터를 정렬하였다. 

측정 신호는 deg, deg/s이지만, 파라미터 피팅에서는 rad, rad/s를 사용하였다.  
측정 신호의 단위와 파라미터 계산에서의 단위가 다르다면, **단위 정합**이 필수이다. 토크의 경우는 사용하는 서보 드라이브와 모터의 모델을 고려해 **모터 정격 토크 기준으로 환산**한다. 


## 3. 물리/제어 과정과 파라미터 설계

- 어떤 물리를 포함할지 선택
- 어떤 파라미터를 식별할지, 어떤 값을 고정할지 설정
- 이 과정에서 모델의 구조를 결정

본 프로젝트의 단일 모터 디지털 트윈은
Command Position → 지령 지연 → PID 제어 → 토크 제한/응답 지연 → 1-DOF 회전축 동역학 → Feedback 구조로 모델링하였다.

포함한 물리
: 1축 회전 관성, PID 제어, 지령 지연, 토크 응답 지연, 토크 제한, 열 부하, 점성·쿨롱 마찰

피팅 파라미터
: kp, ki, kd, inertia, viscous, coulomb, delay_steps, torque_response_time_constant

고정 파라미터
: integral_max, continuous_torque_limit, peak_torque_limit, thermal_time_constant

고정값은 데이터시트 값 또는 사전 설정값을 사용하고, 실측 응답에 직접적인 영향을 크게 주는 파라미터를 중심으로 피팅하였다


## 4. Newton 모델 구축

- 3번에서 정한 구조를 Newton에서 구현
- Newton 모델은 파라미터 기반 응답을 계산하는 시뮬레이션 구현체가 됨
    - Newton 내부 actuator로 표현할지
    - 사용자 코드로 직접 제어식을 쓸지
    - 내부 액츄에이터와 코드로 직접 제어식을 쓰는 방법을 혼합하여 사용할지 판단
    - 어느 수준까지 물리 모델을 단순화 할지 

본 프로젝트에서는 단일 모터를 **1-DOF revolute joint**로 구성하고, 제어기·지연·토크 제한·마찰은 사용자 코드에서 계산하여 Newton 물리계에 반영하였다.  
즉, Newton 내부 actuator를 그대로 사용하는 방식보다, 필요한 제어 및 물리 요소를 직접 구현하는 방식을 선택하였다.

*Newton 내부 actuator만으로는 본 프로젝트에서 고려한 연속 토크 및 열 응답, 토크 응답 지연, 점성·쿨롱 마찰을 모두 표현하기 어려웠기 때문에, 각 요소를 개별적으로 조정하고 실측 데이터에 맞춰 피팅할 수 있도록 직접 구현하는 방식을 선택하였다.
따라서 Newton 내부 actuator 기반 모델의 구성과 실측 데이터 재피팅은 향후 과제로 남겼다.*

현재 프로젝트의 단일 모터 구조는 아래와 같이 요약할 수 있다.

```text
WMX Command Position
        ↓
   지령 지연
 delay_steps
        ↓
서보 드라이브 제어기 근사
 PD 또는 PID
 Kp / Ki / Kd
        ↓
토크 제한
clamping
        ↓
1-DOF Motor Plant
┌─────────────────────┐
│ 관성 J              │
│ 점성마찰 b          │
│ 쿨롱마찰 τc         │
└─────────────────────┘
        ↓
q, q̇, torque
        ↓
WMX Feedback와 비교
```

파라미터 후보는 다음과 같이 나눌 수 있다.

- Drive / Controller: `kp`, `ki`, `kd`, `integral_max`, `delay_steps`
- Motor / Mechanical Plant: `J`(유효 관성), `b`(점성 마찰), `τc`(쿨롱 마찰)
- Limits: `τmax`에 해당하는 토크 제한, 필요 시 속도 제한

토크 제한은 단일 값 하나로만 보지 않고,
연속 토크 제한과 순간 피크 토크 제한을 구분해 다룬다.
현재 구현에서는 피크 제한을 매 제어 주기의 하드 클램프로 적용하고,
연속 제한은 지수 RMS 토크를 이용해 근사하였다.
열 시정수는 단순화한 근사값이므로,
실제 드라이브의 과부하 보호 특성과는 차이가 있을 수 있다.

## 7. 파라미터 식별 

- 초기값을 추정한 뒤 Newton 시뮬레이션 기반으로 파라미터를 최적화한다.
- bounds와 penalty를 적용해 비현실적인 해를 방지한다.
- 오차가 개선된 경우에만 결과를 채택한다.

현재 프로젝트에서는 파형별로 식별 절차를 나누어 적용한다.

- Stop 로그
  토크 noise floor를 확인하고, 토크 오차 해석의 기준으로 사용한다.
- Step 로그
  지연과 과도응답 형상을 확인한다.
  Command Position 변화 이후 토크 또는 응답이 시작되는 시점을 기준으로
  `delay_steps` 후보를 좁히고, 후보별 시뮬레이션 비교로 적절한 지연을 선택할 수 있다.
- Ramp 로그
  정상속도 구간에서 속도와 토크의 관계를 이용해
  `viscous`, `coulomb`의 초기 추정값을 잡는다.
- Multi-sine 로그
  여러 주파수에서의 위치, 속도, 토크 응답을 비교하여
  `kp`, `kd`, `inertia`의 초기값 추정에 사용한다.

Multi-sine 단계의 최적화는 gain/phase를 직접 맞추는 주파수영역 피팅이라기보다,
후보 파라미터로 Newton 시뮬레이션을 수행한 뒤 시간영역의 위치, 속도, 토크 오차를 비교하는 방식에 가깝다.

초기 추정 이후에는 Step, Ramp, Multi-sine에서 얻은 정보를 함께 반영해
전체 파라미터를 미세 조정한다.
이때 위치, 속도, 토크 오차를 정규화한 뒤 가중 평균 loss를 구성할 수 있다.

```text
L = (w_pos·L_pos + w_vel·L_vel + w_trq·L_trq) / (w_pos + w_vel + w_trq)
```

토크 오차는 Stop 로그에서 확인한 noise floor를 기준으로
작은 오차를 deadband 처리할 수 있다.

최적화는 보통 아래와 같은 흐름으로 구성한다.

1. 전역 탐색으로 초기 후보를 찾는다.
2. 국소 최적화로 세부 파라미터를 미세 조정한다.
3. held-out 로그에서 일반화 성능을 확인한다.

예를 들어 현재 프로젝트에서는 `differential_evolution`으로 전역 탐색을 수행하고,
이후 `L-BFGS-B`로 국소 미세조정을 수행하는 방식으로 구성할 수 있다.

## 8. 오차 지표와 검증

- 위치, 속도, 토크 오차를 기준으로 모델 성능 평가
