## 1. 현재 모델의 범위와 한계

### 1.1 현재 모델이 재현하려는 범위

- 현재 모델은 무부하 단일 서보 모터의 평균적인 위치, 속도, 토크 응답을 맞추는 용도이다.
- 저차의 비교적 선형적인 폐루프 모델을 전제로 한다.
- Step, Ramp, 저주파 Sine, held-out S-curve에서 전체 응답 형상을 맞추는 쪽에 초점을 둔다.

### 1.2 현재 모델이 아직 직접 설명하지 못하는 구간

- 방향 전환 근처의 강한 비선형
- stick-slip, deadband
- 속도 추정 노이즈
- 고주파 구간의 세부 토크 파형
- 실제 드라이브 내부의 복잡한 보호 및 제한 로직

### 1.3 결과를 읽을 때 주의할 점

- 현재 모델은 `전체 현실을 모두 복제하는 모델`이 아니라 `설명 가능한 범위 안에서 평균 응답을 맞추는 모델`이다.
- 따라서 최종 평가는 total loss 한 줄보다 Step 과도응답, reversal 근처, held-out S-curve 확대 그림까지 함께 보는 편이 안전하다.

## 2. 현재 선택과 그 이유

### 2.1 왜 raw 1 ms 전체를 그대로 강하게 피팅하지 않았는가

- raw `1 ms` 로그에는 현재 모델이 직접 설명하지 못하는 고주파 성분과 비선형 구간이 함께 섞여 있다.
- 이를 그대로 강하게 넣으면 optimizer가 모델 구조 밖의 현상까지 억지로 맞추려 하면서 전체 피팅이 불안정.
- 그래서 일부 단계에서는 decimate 또는 downsampling을 사용해 평균적인 응답 형상, 진폭, 위상, reversal timing을 우선 맞추는 쪽을 택했다.

현재 모델이 설명 가능한 정보에 더 집중

### 2.2 왜 sine의 고주파 구간을 적극적으로 직접 피팅하지 않았는가
- multi-sine 단계는 모든 파라미터를 한 번에 최종 피팅하는 단계라기보다, 주파수별 응답을 보면서 초기 특성을 읽는 단계에 가깝다.
- 이 단계에서 먼저 보려는 파라미터는 주로 `kp`, `kd`, `inertia`이다.
- 주파수 대역별로 보면 대략 아래처럼 읽을 수 있다.

- `0.1 ~ 0.2 Hz`: `kp`, `coulomb`, `viscous`
- `0.5 ~ 1 Hz`: `kp`, `inertia`, `kd`
- `2 Hz` 이상: `inertia`, `kd`, `delay`, `torque_response_time_constant`

- 위와 비슷한 이유 : 비선형 요소가 많다
- 문제는 실측 모터에는 제어기 내부 비선형, 마찰, stiction, deadband, 속도 추정 노이즈가 함께 섞여 있을 수 있다는 점이다.
- 현재 Newton 단일 모터 모델은 이런 요소를 모두 직접 표현하지 못한다.
- 그래서 고주파를 그대로 강하게 넣으면 평균적인 동특성보다 깨진 구간을 더 따라가게 되고, 파라미터 의미가 흐려질 수 있다.

즉, 고주파를 약하게 다루는 이유는 `현재 모델의 설명 범위와 맞지 않을 수 있어서`이다.

### 2.3 왜 Newton 기본 actuator를 그대로 쓰지 않았는가

- 이번 프로젝트에서 중요하게 본 요소는 지령 지연, 토크 응답 지연, 연속/피크 토크 제한, 점성 마찰, 쿨롱 마찰이었다.
- Newton 기본 actuator로도 일부 항은 다룰 수 있지만, 이 프로젝트에서 원하는 방식으로 세밀하게 분리하고 피팅하기에는 직접 코드 구현이 더 투명했다.
- 그래서 현재 구현에서는 일부 제어 및 제한 요소를 사용자 코드에서 계산하고, Newton 물리계에는 그 결과를 반영하는 방식을 사용했다.

이 선택은 구현 자유도는 높지만, Newton 기본 actuator 기반 모델과 직접 1:1 대응이 약하다는 한계도 함께 가진다.
+ 만약 추후 로봇팔로의 확장 가능성이 있다면 여러가지 물리 법칙과 정의할 것이 많아지기에 actuator 사용이 가지는 장점이 많아진다.

### 2.4 왜 고주파 전용 보정을 당장 하지 않았는가

- 비선형 피팅은 고려하지 않음 + 시간/비선형 요소를 피팅하는 지식 부족
- 사용 대역을 제한한 피팅을 먼저 택함

### 2.5 GPU 환경 관련 메모

- `04_*` 피팅 노트북에는 GPU 또는 CUDA 환경에서 돌릴 수 있도록 넣어 둔 코드가 있다.
    - 0번 셀에 존재. def resolve_sim_device()
- 다만 실제 대상 환경에서 그대로 실행되는지, 의존성과 device 설정이 맞는지는 아직 별도 확인이 필요하다.
- 따라서 `GPU 코드가 들어 있다`와 `실제 재현 가능한 실행 경로가 검증됐다`는 구분해서 봐야 한다.

## 3. 향후 개선과 확장 방향

### 3.1 모델 개선

- Newton actuator 적극적 활용
- reversal 근처 비선형을 더 잘 설명하는 마찰 또는 deadband 모델
- 토크 제한과 토크 응답 지연을 실제 드라이브 거동에 더 가깝게 모델
- 고주파 구간을 억지로 맞추기보다, 현재 모델 차수와 표현 범위를 먼저 확장하는 쪽이 자연스럽다.

### 3.2 Loss 정의 개선

현재는 시간영역 오차 기반 피팅이 중심이지만, 향후에는 loss 정의 자체를 더 다듬을 여지가 있다.

- Parameter regularization: baseline이나 물리적으로 타당한 범위에서 너무 멀어지지 않도록 제약을 줄 수 있다.
- Shape 중심 loss: 점별 미세 오차보다 rise, overshoot, reversal, envelope 같은 응답 형상을 더 직접 반영할 수 있다.
- Filtered 또는 band-limited loss: 현재 모델이 설명 가능한 주파수 대역에 맞춰 비교 신호를 제한할 수 있다.
